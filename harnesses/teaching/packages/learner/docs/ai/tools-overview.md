# Tools overview (students)

You are **not required** to use local coding agents unless a course says so. Browser assistants are fine when they fit course rules.

## Common options

| Kind | Examples | Typical use |
|:--|:--|:--|
| **Chat (browser)** | ChatGPT, Claude.ai, Gemini, Copilot chat | Concepts, debug help, outlines |
| **IDE assist** | Copilot, inline complete | Boilerplate, small edits |
| **Local agents** | Claude Code, Codex CLI, Grok/Cursor agents | Multi-file coding in a repo |
| **Course materials** | GitHub repo, Pages hub | Readings, labs, sample data |

## If your course provides agent config

Some materials repos include `AGENTS.md` or skill folders for **optional** tools. Those files guide the *tools*. They do **not** replace:

- Syllabus / LMS  
- [ai-what-to-expect.md](ai-what-to-expect.md)  
- This kit’s workflow  

## Practical advice

1. **Start simple** — chat + your editor is enough for most labs.  
2. **One tool well** beats five tools poorly.  
3. **Never** point a cloud agent at restricted data directories.  
4. Keep graded work **yours**—agents draft; you verify and own.  

## Optional: student `AGENTS.md`

If you use agents on **your** project clone, a short project `AGENTS.md` can say:

- Prefer public samples under `data/public/`  
- Don’t commit secrets or MIMIC extracts  
- Disclose AI use per course rules  

A starter file may ship as `packages/shared/AGENTS.md` in this kit.
